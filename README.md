# MyImGuiMetalProject

Обобщённая обёртка над графическими API: один цикл кадра (`FastRenderer::run_loop()`) поверх
абстракций из `render_pipeline/`, с бэкендами Metal (`render_metal/`) и Vulkan (`render_vulkan/`).

Один и тот же код приложения даёт одинаковую картинку на Windows и macOS.

## Возможности

* Многопроходные схемы: оффскрин-цели, несколько целей за проход, сэмплирование результатов
* Глубина, трафарет, смешивание, отсечение граней, смещение глубины
* Сглаживание (MSAA) со сведением
* Текстуры: загрузка, мип-цепочки, объёмы, кубические карты, массивы, блочное сжатие BC
* Размещение в видеопамяти через промежуточный буфер, измерение бюджета, суб-аллокация
* Push-константы, кэш привязок, непрямая отрисовка
* Чтение данных с GPU (скриншоты, выбор объектов, автоматические проверки)

Честный список того, чего нет, — в конце
[справочника](docs/API.ru.md#16-ограничения-и-то-чего-нет), в
[последней главе первой книги](docs/book/08-lovushki.ru.md#208-чего-в-рендерере-нет) и, с оценкой
трудоёмкости каждой доработки, в [главе 13 второй](docs/scenes/13-ogranicheniya.ru.md).

## Сборка

```
cmake -B build
cmake --build build --config Release
```

Требуется Vulkan SDK на Windows (для `glslc`) и Xcode на macOS.

## Просмотрщик сцен

`FastRenderer.cpp` — это просмотрщик, рассчитанный на сцены из архива
[casual-effects.com/data](https://casual-effects.com/data/index.html).

```
DMRENDER_MODEL=path/to/scene.obj  build/Release/RenderingApp
```

Без переменной окружения ищутся `assets/San_Miguel/san-miguel*.obj` и `bunny.obj`, поднимаясь на
несколько каталогов вверх — так работает и запуск из `build/Release`, и из корня проекта.

| Переменная | Что делает |
|---|---|
| `DMRENDER_MODEL` | Путь к сцене (`.obj`, `.stl`, `.ply`) |
| `DMRENDER_SCREENSHOT` | Префикс пути: отрисовать шесть ракурсов в PNG и выйти, без окна |
| `DMRENDER_BENCH` | Число повторов на ракурс для замера времени кадра |
| `DMRENDER_NOSHADOW` | Запустить с выключенными тенями |
| `DMRENDER_DUMP_CASCADES` | Выгрузить сами карты теней в PNG (диагностика) |

Управление: перетаскивание мышью — обзор, `WASD` — движение, `Q`/`E` — вниз/вверх, `Shift` —
быстро, `Ctrl` — медленно. Остальное в панели.

**Кеш сцены.** Первый разбор `san-miguel.obj` (1.1 ГБ текста) занимает около девяти секунд;
результат сохраняется рядом как `.dmcache`, и последующие запуски читают его за 0.15 с. Кеш
инвалидируется по размеру и времени изменения исходного файла.

**Ассеты в репозиторий не входят.** Скачайте архив со страницы сцены и распакуйте так, чтобы
получилось `assets/San_Miguel/san-miguel.obj` рядом с каталогом проекта.

**Тени.** Четыре каскада 2048×2048 для солнца. Хранится не глубина, а **расстояние в мировых
единицах** в цветовой цели `R32_FLOAT`: буфер глубины в этой обёртке нельзя сэмплировать, а
сравнивающего сэмплера нет. Зато смещения задаются в текселях и сантиметрах, а не в безразмерных
единицах буфера. Объём каскада подгоняется по ограничивающей **сфере** среза пирамиды видимости и
привязывается к сетке текселей — без этого края теней кипят при движении камеры. Смещение —
вдоль нормали, ручной PCF 3×3, отдельный вариант шейдера с `discard` для листвы.

Что просмотрщик берёт из второй книги: reverse-Z и точность глубины (гл. 3), загрузка текстур в
потоках, sRGB и анизотропная фильтрация (гл. 4), отсечение по пирамиде, сортировка по
пайплайну/материалу/глубине и непрямая отрисовка (гл. 5), микрофасетная BRDF и тонмаппинг
(гл. 6), каскадные карты теней (гл. 8), вырезание по альфа-маске и сортированная прозрачность
(гл. 9), компактная вершина и бинарный кеш (гл. 12).
