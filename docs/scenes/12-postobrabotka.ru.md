# Часть XII. Постобработка

> **Цель главы.** Превратить корректную картинку в красивую. Свечение, автоматическая экспозиция,
> контактное затенение и сглаживание — четыре эффекта, каждый из которых упирается в
> пропускную способность, а не в арифметику. Здесь мы будем считать байты чаще, чем в любой другой
> главе.

---

## 12.1. Железо: постобработка — это трафик

Каждый полноэкранный проход читает как минимум один полноэкранный буфер и пишет другой. При
2560×1440:

| Формат | Байт/пиксель | Полный кадр |
|---|---|---|
| `RGBA8_UNORM` | 4 | 14.8 МБ |
| `RGBA16_FLOAT` | 8 | 29.6 МБ |
| `R32_FLOAT` | 4 | 14.8 МБ |

Проход «прочитать RGBA16F и записать RGBA16F» стоит 59 МБ. При 60 кадрах — **3.5 ГБ/с за один
проход**. Пять таких проходов — 17.5 ГБ/с, и это уже пятая часть шины ноутбучного чипа.

Арифметика при этом смехотворна: размытие по девяти точкам — это девять выборок и несколько
сложений. **Постобработка почти всегда упирается в память.** Отсюда две стратегии, к которым мы
будем возвращаться:

**Работать в уменьшенном разрешении.** Проход в половинном разрешении стоит вчетверо дешевле.
Свечение и затенение — низкочастотные по природе, и уменьшение на них почти не сказывается.

**Объединять проходы.** Тонмаппинг, виньетка, зернистость и цветокоррекция — это всё арифметика
над одним пикселем. Делать их одним проходом вместо четырёх — экономия в четыре раза, без потери
качества вообще.

## 12.2. Ограничение: нельзя рендерить в уровень мипа

Прежде чем строить цепочки уменьшения, надо назвать ограничение обёртки, которое определяет
архитектуру всей главы.

`RenderPassDescriptor::setColorAttachment()` принимает номер **слоя** массива, но **не** номер
уровня мипа. То есть отрендерить в мип 1 существующей текстуры нельзя.

Практически это значит: цепочка уменьшения строится не как мипы одной текстуры, а как **набор
отдельных изображений** уменьшающегося размера.

```cpp
struct DownsampleChain {
    std::vector<std::shared_ptr<GImage>> levels;   // 0 — полный размер
};

DownsampleChain createChain(const std::shared_ptr<Device>& device,
                            uint32_t width, uint32_t height,
                            ImageFormat format, uint32_t levelCount,
                            const char* name)
{
    DownsampleChain chain;
    for (uint32_t i = 0; i < levelCount && width > 1 && height > 1; ++i) {
        ImageDesc desc{};
        desc.format = format;
        desc.width  = std::max(1u, width);
        desc.height = std::max(1u, height);
        desc.usage  = ImageUsage::ColorTarget | ImageUsage::Sampled;
        desc.debugName = std::string(name) + std::to_string(i);
        chain.levels.push_back(device->createImage(desc));
        width  /= 2;
        height /= 2;
    }
    return chain;
}
```

Расход памяти тот же, что у мип-цепочки (сумма геометрической прогрессии — около 1⅓ от полного
размера), лишних затрат нет. Неудобство чисто организационное: изображений много, и их надо
пересоздавать при изменении размера окна. `generateMipmaps()` здесь не подходит — она делает
простое усреднение, а нам нужна выборка с фильтром и порогом.

## 12.3. Свечение (bloom)

### Что это физически

Свечение вокруг ярких объектов — не художественный приём, а оптический артефакт. Свет
рассеивается в хрусталике глаза, на несовершенствах линз объектива, на пыли. Яркий источник
«растекается» на соседние области. Без свечения яркое на экране не читается как яркое: монитор
физически не может выдать нужную светимость, и убедить глаз можно только через этот артефакт.

Именно поэтому свечение выглядит естественно, а его отсутствие в HDR-сцене — нет.

### Алгоритм

```
HDR-кадр
   │
   ▼ проход яркости (порог, половинное разрешение)
уровень 0
   │
   ▼ уменьшение ×5
уровень 1 … 5
   │
   ▼ увеличение с суммированием (аддитивное смешивание)
уровень 0
   │
   ▼ смешивание с HDR в проходе тонмаппинга
готово
```

### Проход яркости

```metal
fragment float4 bloom_prefilter(FullscreenOut in [[stage_in]],
                                constant float4& params [[buffer(8)]],
                                texture2d<float> hdr [[texture(0)]],
                                sampler smp [[sampler(0)]])
{
    float3 color = hdr.sample(smp, in.uv).rgb;

    // Яркость по стандартным весам восприятия: глаз чувствительнее к зелёному.
    const float luminance = dot(color, float3(0.2126, 0.7152, 0.0722));

    // Мягкий порог: жёсткое отсечение даёт мерцающую границу там, где
    // яркость колеблется около порога от кадра к кадру.
    const float threshold = params.x;
    const float knee      = params.y;
    const float soft = clamp(luminance - threshold + knee, 0.0, 2.0 * knee);
    const float contribution =
        max(soft * soft / (4.0 * knee + 1e-5), luminance - threshold) /
        max(luminance, 1e-5);

    // Ограничение сверху: одиночный пиксель яркостью 10000 иначе даст
    // «светлячка» — мерцающую точку, которая расплывается в пятно.
    color = min(color, float3(params.z));

    return float4(color * max(contribution, 0.0), 1.0);
}
```

Ограничение сверху (`params.z`, обычно 8–32) обязательно. Без него единичный очень яркий пиксель —
блик на металле, солнце в щели — даёт мерцающее пятно, и это самый заметный дефект наивного
свечения.

### Уменьшение и увеличение

```metal
// Уменьшение: 13 выборок «по кругу» вместо 4. Даёт заметно более
// стабильную картинку при движении — простое усреднение 2×2 мерцает.
fragment float4 bloom_downsample(FullscreenOut in [[stage_in]],
                                 constant float2& texelSize [[buffer(8)]],
                                 texture2d<float> source [[texture(0)]],
                                 sampler smp [[sampler(0)]])
{
    const float2 t = texelSize;
    float3 sum = float3(0.0);

    // Центральный блок 2×2 — вес 0.5 суммарно
    sum += source.sample(smp, in.uv + float2(-t.x,  t.y) * 0.5).rgb * 0.125;
    sum += source.sample(smp, in.uv + float2( t.x,  t.y) * 0.5).rgb * 0.125;
    sum += source.sample(smp, in.uv + float2(-t.x, -t.y) * 0.5).rgb * 0.125;
    sum += source.sample(smp, in.uv + float2( t.x, -t.y) * 0.5).rgb * 0.125;

    // Внешние блоки
    sum += source.sample(smp, in.uv).rgb * 0.125;
    sum += source.sample(smp, in.uv + float2(-t.x,  0.0)).rgb * 0.0625;
    sum += source.sample(smp, in.uv + float2( t.x,  0.0)).rgb * 0.0625;
    sum += source.sample(smp, in.uv + float2( 0.0, -t.y)).rgb * 0.0625;
    sum += source.sample(smp, in.uv + float2( 0.0,  t.y)).rgb * 0.0625;
    sum += source.sample(smp, in.uv + float2(-t.x,  t.y)).rgb * 0.03125;
    sum += source.sample(smp, in.uv + float2( t.x,  t.y)).rgb * 0.03125;
    sum += source.sample(smp, in.uv + float2(-t.x, -t.y)).rgb * 0.03125;
    sum += source.sample(smp, in.uv + float2( t.x, -t.y)).rgb * 0.03125;

    return float4(sum, 1.0);
}

// Увеличение: тент-фильтр 3×3. Результат ПРИБАВЛЯЕТСЯ к более крупному
// уровню аддитивным смешиванием — отдельного прохода сложения не нужно.
fragment float4 bloom_upsample(FullscreenOut in [[stage_in]],
                               constant float2& texelSize [[buffer(8)]],
                               texture2d<float> source [[texture(0)]],
                               sampler smp [[sampler(0)]])
{
    const float2 t = texelSize;
    float3 sum = float3(0.0);
    sum += source.sample(smp, in.uv + float2(-t.x,  t.y)).rgb * 0.0625;
    sum += source.sample(smp, in.uv + float2( 0.0,  t.y)).rgb * 0.125;
    sum += source.sample(smp, in.uv + float2( t.x,  t.y)).rgb * 0.0625;
    sum += source.sample(smp, in.uv + float2(-t.x,  0.0)).rgb * 0.125;
    sum += source.sample(smp, in.uv).rgb                      * 0.25;
    sum += source.sample(smp, in.uv + float2( t.x,  0.0)).rgb * 0.125;
    sum += source.sample(smp, in.uv + float2(-t.x, -t.y)).rgb * 0.0625;
    sum += source.sample(smp, in.uv + float2( 0.0, -t.y)).rgb * 0.125;
    sum += source.sample(smp, in.uv + float2( t.x, -t.y)).rgb * 0.0625;
    return float4(sum, 1.0);
}
```

Ключевой момент: увеличение использует **аддитивное смешивание** (`BlendState::additive()`), и
результат прибавляется прямо к уровню, который уже там лежит. Проход суммирования не нужен, и это
экономит по проходу на уровень.

**Сэмплер здесь — `Linear` с `ClampToEdge`.** Линейная фильтрация здесь именно то, что нужно:
каждая выборка бесплатно усредняет четыре тексела, и 13-точечный фильтр фактически покрывает 52
тексела. `Repeat` дал бы затягивание яркости с противоположного края экрана.

### Стоимость

```
Проход яркости (½ разрешения):  чтение 29.6 + запись 7.4 = 37 МБ
5 уменьшений:                   ~12 МБ суммарно (быстро мельчают)
5 увеличений:                   ~24 МБ (чтение + запись со смешиванием)
                                ──────
                                ~73 МБ/кадр → 4.4 ГБ/с
```

Одиннадцать дополнительных проходов. На дискретной карте — незаметно. На Apple Silicon каждый
`beginRenderPass` — это работа с тайлами, и одиннадцать проходов ощутимы. Если бюджет жмёт,
уменьшите число уровней до трёх: свечение станет менее «широким», но останется убедительным.

## 12.3a. Автоматическая экспозиция

Глаз адаптируется к яркости. Выходя из тёмной арки Sponza на солнце, человек сначала слепнет, а
потом привыкает. Без этого сцена с большим перепадом яркостей либо слепит, либо тонет.

Задача: свести весь кадр к одному числу — средней яркости — и медленно к нему подстраиваться.

Свёртка к одному числу обычно делается вычислительным шейдером, которого у нас нет. Доступный
путь — **цепочка уменьшающих проходов до 1×1**. С коэффициентом 4 по каждой оси от 2560×1440 до
единицы нужно шесть проходов, и все, кроме первого, работают с крошечными изображениями.

```
2560×1440 → 640×360 → 160×90 → 40×23 → 10×6 → 3×2 → 1×1
```

Первый проход пишет логарифм яркости (среднее геометрическое ближе к восприятию, чем
арифметическое), остальные просто усредняют.

Адаптация во времени — через два изображения 1×1, меняющихся местами:

```metal
fragment float exposure_adapt(FullscreenOut in [[stage_in]],
                              constant float3& params [[buffer(8)]],  // dt, скорость вверх/вниз
                              texture2d<float> currentLuminance [[texture(0)]],
                              texture2d<float> previousExposure [[texture(1)]],
                              sampler smp [[sampler(0)]])
{
    const float target   = exp(currentLuminance.sample(smp, float2(0.5)).r);
    const float previous = previousExposure.sample(smp, float2(0.5)).r;

    // Адаптация к темноте медленнее, чем к свету — как у глаза.
    const float speed = (target > previous) ? params.y : params.z;
    return previous + (target - previous) * (1.0 - exp(-params.x * speed));
}
```

Экспоненциальная адаптация, а не линейная: это и физиологически ближе, и не зависит от частоты
кадров.

Читать результат в проход тонмаппинга — обычной выборкой из текстуры 1×1. **`readback()`
использовать нельзя**: он синхронен и ждёт простоя видеокарты, то есть съедает всю
асинхронность из главы 11. Он для инструментов, не для кадра.

Если шесть дополнительных проходов кажутся неоправданными — ползунок экспозиции в интерфейсе
решает 90 % задачи для сцены с фиксированным освещением, а все сцены архива именно такие.

## 12.4. Экранное затенение (SSAO)

### Что это

Прямое освещение из главы 7 не знает про самозатенение геометрии. Углы комнаты, стыки, щели под
мебелью должны быть темнее — туда попадает меньше рассеянного света со всех сторон. Полный расчёт
— это глобальное освещение; SSAO даёт дешёвое приближение, используя то, что уже есть в G-буфере.

Идея: вокруг точки берём случайные точки в полусфере по нормали и проверяем по буферу глубины,
находятся ли они «внутри» геометрии. Доля попавших внутрь и есть затенение.

Всё нужное у нас уже есть: **линейная глубина и нормаль лежат в G-буфере** (глава 8). Отдельных
проходов геометрии не требуется.

### Реализация

```metal
constant constexpr uint kSampleCount = 16;

fragment float ssao_fragment(FullscreenOut in [[stage_in]],
                             constant SsaoUniforms& params [[buffer(1)]],
                             texture2d<float> gNormal [[texture(0)]],
                             texture2d<float> gDepth  [[texture(1)]],
                             texture2d<float> noise   [[texture(2)]],
                             sampler pointSampler  [[sampler(0)]],
                             sampler repeatSampler [[sampler(2)]])
{
    const float linearDepth = gDepth.sample(pointSampler, in.uv).r;
    if (linearDepth >= params.farDistance) return 1.0;      // небо не затеняем

    const float3 viewPosition = viewPositionFromDepth(in.uv, linearDepth,
                                                      params.tanHalfFov, params.aspect);

    // Нормаль в G-буфере мировая — переводим в пространство вида.
    const float3 worldNormal = normalize(gNormal.sample(pointSampler, in.uv).xyz);
    const float3 N = normalize((params.view * float4(worldNormal, 0.0)).xyz);

    // Случайный поворот на пиксель. Текстура шума 4×4 повторяется по экрану;
    // без неё видны регулярные полосы вместо шума.
    const float2 noiseScale = float2(params.screenWidth, params.screenHeight) / 4.0;
    const float3 randomVector = noise.sample(repeatSampler, in.uv * noiseScale).xyz * 2.0 - 1.0;

    // Базис Грама–Шмидта вокруг нормали.
    const float3 T = normalize(randomVector - N * dot(randomVector, N));
    const float3 B = cross(N, T);
    const float3x3 tbn = float3x3(T, B, N);

    float occlusion = 0.0;
    for (uint i = 0; i < kSampleCount; ++i) {
        const float3 samplePosition =
            viewPosition + (tbn * params.kernel[i].xyz) * params.radius;

        // Проецируем точку обратно на экран.
        const float4 clip = params.projection * float4(samplePosition, 1.0);
        const float2 ndc  = clip.xy / clip.w;
        const float2 uv   = float2(ndc.x * 0.5 + 0.5, 0.5 - ndc.y * 0.5);

        const float sceneDepth = gDepth.sample(pointSampler, uv).r;

        // Проверка диапазона: без неё далёкий объект на фоне даёт
        // ложное затенение — «ореол» вокруг силуэтов.
        const float rangeCheck =
            smoothstep(0.0, 1.0, params.radius / abs(linearDepth - sceneDepth));

        // Точка выборки глубже, чем сцена в этом месте → она внутри геометрии.
        occlusion += (sceneDepth < -samplePosition.z - params.bias) ? rangeCheck : 0.0;
    }

    return 1.0 - occlusion / float(kSampleCount);
}
```

Ядро выборок готовится на CPU один раз: случайные точки в полусфере, смещённые к центру, чтобы
ближние вносили больший вклад.

```cpp
std::vector<Vec4> buildKernel(uint32_t count)
{
    std::mt19937 rng(12345);       // фиксированное зерно: воспроизводимость
    std::uniform_real_distribution<float> unit(0.0f, 1.0f);
    std::uniform_real_distribution<float> signed01(-1.0f, 1.0f);

    std::vector<Vec4> kernel;
    for (uint32_t i = 0; i < count; ++i) {
        Vec3 v { signed01(rng), signed01(rng), unit(rng) };   // z ≥ 0: полусфера
        v = normalize(v) * unit(rng);

        // Квадратичное сгущение к центру: ближние выборки важнее.
        float scale = static_cast<float>(i) / count;
        scale = 0.1f + 0.9f * scale * scale;
        kernel.push_back({ v.x * scale, v.y * scale, v.z * scale, 0.0f });
    }
    return kernel;
}
```

**Обязательное размытие после.** Шумовая текстура 4×4 даёт заметный узор. После SSAO идёт
размытие 4×4, ровно совпадающее с периодом шума — тогда узор усредняется в точности.

**Работайте в половинном разрешении.** Затенение низкочастотно, разница почти не видна, а стоимость
падает вчетверо. При 16 выборках в полном разрешении это 59 млн выборок на кадр — самая дорогая
часть постобработки.

**Радиус — в мировых единицах**, и его надо соотносить с масштабом сцены. Для Sponza в
сантиметрах радиус 0.5 не даст ничего.

## 12.5. Сглаживание

MSAA нам недоступен в отложенной схеме (глава 8): многовыборочное изображение нельзя объявить
`Sampled`. Остаётся постобработка.

### FXAA

Ищет края по перепаду яркости и размывает **вдоль** края. Один проход, никакой дополнительной
информации не требует.

```metal
fragment float4 fxaa_fragment(FullscreenOut in [[stage_in]],
                              constant float2& texelSize [[buffer(8)]],
                              texture2d<float> source [[texture(0)]],
                              sampler smp [[sampler(0)]])
{
    const float3 weights = float3(0.2126, 0.7152, 0.0722);

    auto luma = [&](float2 offset) {
        return dot(source.sample(smp, in.uv + offset * texelSize).rgb, weights);
    };

    const float center = luma(float2( 0,  0));
    const float north  = luma(float2( 0, -1));
    const float south  = luma(float2( 0,  1));
    const float west   = luma(float2(-1,  0));
    const float east   = luma(float2( 1,  0));

    const float minLuma = min(center, min(min(north, south), min(west, east)));
    const float maxLuma = max(center, max(max(north, south), max(west, east)));
    const float range   = maxLuma - minLuma;

    // Плоская область — края нет, выходим. Это ветвление КОГЕРЕНТНО
    // в пространстве экрана (глава 1), поэтому реально экономит.
    if (range < max(0.0312, maxLuma * 0.125)) {
        return source.sample(smp, in.uv);
    }

    // Направление края: перпендикулярно градиенту яркости.
    float2 direction = float2(-((north + south) - 2.0 * center),
                                (west + east)  - 2.0 * center);
    const float length2 = max(abs(direction.x), abs(direction.y));
    direction = clamp(direction / max(length2, 1e-5), -8.0, 8.0) * texelSize;

    const float3 a = source.sample(smp, in.uv + direction * (1.0 / 3.0 - 0.5)).rgb;
    const float3 b = source.sample(smp, in.uv + direction * (2.0 / 3.0 - 0.5)).rgb;
    return float4((a + b) * 0.5, 1.0);
}
```

**FXAA применяется к финальному изображению после тонмаппинга и кодирования в sRGB.** Это важно:
он работает с воспринимаемой яркостью, а в линейном пространстве перепады выглядят иначе, и
детектор краёв сработает неверно.

Плюсы: один проход, ничего не требует. Минусы: размывает мелкие детали и текст, ничего не делает
с мерцанием при движении.

### TAA — и что для него понадобится

Временное сглаживание накапливает выборки **по кадрам**: каждый кадр проекция смещается на долю
пикселя, и результат смешивается с предыдущим. Даёт качество лучше MSAA и попутно убирает
мерцание.

Для полноценного TAA нужны три вещи, две из которых мы можем, а третья требует работы:

1. **Дрожание проекции.** Легко: сдвиг матрицы проекции по последовательности Холтона.
2. **История.** Два изображения полного размера, меняющихся местами. Легко.
3. **Буфер скоростей.** Для каждого пикселя — куда он сместился с прошлого кадра. Требует
   **дополнительной цели в G-буфере** (`RGBA16_FLOAT`, +8 байт на пиксель) и хранения матрицы
   `viewProjection` предыдущего кадра, а для скиннингованных объектов — ещё и предыдущих матриц
   костей.

Без буфера скоростей TAA даёт смазывание при движении камеры. С ним — работает, но появляется
задача отбраковки истории (neighbourhood clamping), и это тема отдельного выпуска.

Практическая рекомендация для курса: **FXAA как базовый вариант**, TAA — как задел. На статичных
сценах архива, где камера двигается плавно и медленно, FXAA даёт вполне приличный результат.

## 12.6. Порядок и объединение

Полная цепочка кадра:

```
1. Проход G-буфера          (непрозрачное)
2. SSAO                     (½ разрешения, из G-буфера)
3. Размытие SSAO            (½ разрешения)
4. Проход освещения         → HDR, затенение умножается на рассеянную часть
5. Прозрачное               (прямой проход поверх HDR)
6. Яркость для свечения     (½ разрешения)
7. Уменьшения ×5
8. Увеличения ×5            (аддитивно)
9. Экспозиция               (цепочка до 1×1, раз в кадр)
10. Тонмаппинг + свечение + виньетка + зернистость + sRGB  ← ОДИН проход
11. FXAA                    → свопчейн
12. Интерфейс               (clear = false)
```

Шаг 10 — то самое объединение. Все эти операции — арифметика над одним пикселем, и делать их
одним проходом вместо пяти экономит четыре чтения и четыре записи полного кадра, то есть около
240 МБ на кадр при 2560×1440.

```metal
fragment float4 composite_fragment(FullscreenOut in [[stage_in]],
                                   constant CompositeParams& params [[buffer(1)]],
                                   texture2d<float> hdr       [[texture(0)]],
                                   texture2d<float> bloom     [[texture(1)]],
                                   texture2d<float> exposure  [[texture(2)]],
                                   sampler smp [[sampler(0)]])
{
    float3 color = hdr.sample(smp, in.uv).rgb;

    // Свечение подмешивается, а не прибавляется: сумма увела бы
    // среднюю яркость кадра вверх.
    color = mix(color, bloom.sample(smp, in.uv).rgb, params.bloomStrength);

    color /= max(exposure.sample(smp, float2(0.5)).r, 1e-4);
    color = tonemapACES(color);

    // Виньетка: затемнение к краям, имитация спада яркости объектива.
    const float2 centered = in.uv - 0.5;
    color *= 1.0 - dot(centered, centered) * params.vignetteStrength;

    // Зернистость: разрывает полосатость в градиентах.
    const float grain = fract(sin(dot(in.uv, float2(12.9898, 78.233)) +
                                  params.time) * 43758.5453);
    color += (grain - 0.5) * params.grainStrength;

    return float4(linearToSrgb(saturate(color)), 1.0);
}
```

Порядок внутри прохода критичен и совпадает с физикой: свечение и экспозиция — **в линейном
пространстве, до тонмаппинга**; виньетка — после (она про объектив, а не про сцену); зернистость
— в самом конце; кодирование в sRGB — последним всегда.

### Бюджет

```
SSAO + размытие (½)     ~30 МБ
Свечение (11 проходов)  ~73 МБ
Экспозиция              ~15 МБ (первый проход дорогой, остальные нет)
Сведение                ~44 МБ
FXAA                    ~30 МБ
                        ───────
                        ~192 МБ/кадр → 11.5 ГБ/с при 60 Гц
```

Плюс 177 МБ отложенного рендеринга из главы 8 — итого около **370 МБ на кадр, 22 ГБ/с**.

На дискретной карте с 400+ ГБ/с — 5 %, свободно. На чипе M-класса со 100 ГБ/с — **22 % шины
только на графику**, при том что процессор в той же памяти. Это уже граница, за которой надо
выбирать: половинное разрешение для SSAO и свечения, меньше уровней, отказ от автоэкспозиции.

**Считайте байты.** Это главный навык всей книги, и здесь он нужен больше, чем где-либо.

## 12.6a. Развлечение: экран электронно-лучевой трубки

Проход сведения — удобное место, чтобы показать, как из нескольких дешёвых искажений получается
узнаваемый образ. Соберём старый монитор: изгиб стекла, строчную развёртку, теневую маску и
хроматическую аберрацию. Всё это — арифметика над одним пикселем, то есть один проход поверх
готового кадра.

```metal
// 1. Изгиб стекла. Отталкиваемся от центра: чем дальше, тем сильнее сдвиг.
float2 curveScreen(float2 uv, float amount)
{
    float2 centered = uv * 2.0 - 1.0;
    // Кривизна по одной оси зависит от координаты по ДРУГОЙ — так получается
    // бочка, а не два независимых растяжения.
    centered.x *= 1.0 + pow(abs(centered.y) * amount, 2.0);
    centered.y *= 1.0 + pow(abs(centered.x) * amount, 2.0);
    return centered * 0.5 + 0.5;
}

fragment float4 crt_fragment(FullscreenOut in [[stage_in]],
                             constant CrtParams& params [[buffer(8)]],
                             texture2d<float> source [[texture(0)]],
                             sampler          smp    [[sampler(0)]])
{
    const float2 uv = curveScreen(in.uv, params.curvature);

    // За краем изогнутого стекла — чёрная рамка корпуса.
    if (any(uv < 0.0) || any(uv > 1.0)) return float4(0.0, 0.0, 0.0, 1.0);

    // 2. Хроматическая аберрация: линза преломляет цвета по-разному, поэтому
    //    каналы читаются с чуть разным смещением от центра. Величина растёт
    //    к краям — там угол падения больше.
    const float2 fromCentre = uv - 0.5;
    const float  aberration = params.aberration * dot(fromCentre, fromCentre);
    const float3 color = float3(
        source.sample(smp, uv + fromCentre * aberration).r,
        source.sample(smp, uv).g,
        source.sample(smp, uv - fromCentre * aberration).b);

    // 3. Строчная развёртка: луч рисует через строку, между строками темнее.
    //    Период — в ПИКСЕЛЯХ цели, иначе полосы поедут при смене разрешения.
    const float scanline = 0.5 + 0.5 * cos(in.position.y * 3.14159);
    float3 result = color * mix(1.0, scanline, params.scanlineStrength);

    // 4. Теневая маска: три люминофора на пиксель, по одному на канал.
    //    fmod по X даёт повторяющуюся тройку RGB.
    const int   subpixel = int(in.position.x) % 3;
    const float3 mask = (subpixel == 0) ? float3(1.0, 0.7, 0.7)
                      : (subpixel == 1) ? float3(0.7, 1.0, 0.7)
                                        : float3(0.7, 0.7, 1.0);
    result *= mix(float3(1.0), mask, params.maskStrength);

    // 5. Виньетка: свечение люминофора к краям слабее.
    result *= 1.0 - dot(fromCentre, fromCentre) * params.vignette;

    // Компенсация: маска и развёртка съели около трети яркости.
    return float4(result * params.gain, 1.0);
}
```

Помимо ностальгии здесь три приёма, которые пригодятся в серьёзной постобработке:

**Искажение координаты вместо искажения картинки.** Мы не двигаем пиксели — мы читаем из другого
места. Так устроены все экранные искажения: линза, тепловое марево, рябь на воде, эффект
опьянения. Дорогая часть — это дополнительные выборки, а не арифметика.

**Хроматическая аберрация — три выборки со сдвигом по каналам.** Ровно та же схема, только сдвиг
разный для R, G и B. В сдержанной дозировке (`aberration` порядка 0.01) она применяется в
современных играх постоянно, просто её не замечают.

**Периодические узоры надо привязывать к пикселям, а не к UV.** `in.position.y` — пиксельная
координата (глава 2), и полосы получаются толщиной ровно в пиксель на любом разрешении. Если взять
`in.uv.y * height`, результат тот же, но об этом легко забыть и получить полосы, меняющие толщину
при изменении размера окна.

Компенсация яркости в конце — не мелочь: маска и развёртка отнимают около трети, и без множителя
картинка просто темнеет. Настоящая трубка компенсировала это тем, что светилась ярче между
строками.

## 12.7. Что обычно ломается

| Симптом | Причина |
|---|---|
| Свечение мерцает на бликах | Нет ограничения яркости в проходе порога |
| Свечение затягивается с края экрана | Сэмплер `Repeat` вместо `ClampToEdge` |
| Свечение квадратное, ступенчатое | Сэмплер `Nearest` вместо `Linear` |
| SSAO шумит регулярным узором | Размытие не совпадает по размеру с текстурой шума |
| Тёмный ореол вокруг силуэтов | Нет проверки диапазона в SSAO |
| SSAO ничего не даёт | Радиус не соответствует масштабу сцены |
| Небо затенено | Не отброшены пиксели с максимальной глубиной |
| FXAA размывает всё подряд | Применён к линейному HDR, а не к финальному sRGB |
| Экспозиция дёргается | Линейная адаптация вместо экспоненциальной |
| Всё стало медленным | Слишком много полноэкранных проходов. Объедините |
| На Mac просадка сильнее, чем на PC | Каждый проход — работа с тайлами. Уменьшайте число проходов |

## 12.8. Проверка

1. **Свечение.** Яркий маленький объект на тёмном фоне. Ореол должен быть плавным, круглым и
   **неподвижным** при движении камеры. Мерцание — не хватает ограничения яркости.
2. **SSAO отдельным выводом.** Углы стен и стыки тёмные, открытые плоскости белые. Ореолов вокруг
   силуэтов быть не должно.
3. **Экспозиция.** Заведите камеру из тёмной арки Sponza на яркий двор. Должно быть плавное
   привыкание за 1–2 секунды, к темноте — медленнее.
4. **FXAA.** Скриншоты до и после, увеличенная диагональная грань. Ступеньки должны сгладиться;
   если текст интерфейса тоже размылся — FXAA применён до отрисовки интерфейса, переставьте.
5. **Бюджет.** Включайте эффекты по одному и записывайте время кадра. Составьте таблицу
   «эффект — миллисекунды». Она пригодится в главе 13, когда придётся чем-то жертвовать.

## Итог

1. Постобработка упирается в **память**, а не в арифметику. Две стратегии: половинное разрешение
   и объединение проходов.
2. **Рендерить в уровень мипа наша обёртка не умеет** — цепочки уменьшения строятся из отдельных
   изображений.
3. Свечение: порог с мягким краем и **обязательным ограничением сверху**, цепочка
   уменьшение-увеличение, увеличение через аддитивное смешивание.
4. Автоэкспозиция — цепочка проходов до 1×1 и экспоненциальная адаптация. **`readback()`
   использовать нельзя**: он синхронен.
5. SSAO берёт всё из G-буфера. Обязательны шумовая текстура, проверка диапазона и размытие,
   совпадающее по размеру с шумом.
6. FXAA работает **после** тонмаппинга и sRGB. TAA потребует буфера скоростей — ещё одной цели
   G-буфера.
7. Объединяйте всё, что можно, в один проход сведения. Порядок: свечение и экспозиция в линейном
   пространстве, виньетка и зерно после тонмаппинга, sRGB последним.
