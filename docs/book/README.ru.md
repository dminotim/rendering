# Кроссплатформенный рендерер с нуля

Курс по построению обобщённого графического слоя поверх Vulkan и Metal — от пустого проекта до
рабочего рендерера с многопроходной схемой, сжатыми текстурами, объёмами и непрямой отрисовкой.

Материал написан как основа для длинной видеосерии: каждая глава — один-два выпуска, с чётким
результатом, который видно на экране, и с объяснением **почему** сделано именно так. Ошибки,
которые мы допустили при реальной разработке, оставлены в тексте намеренно — они полезнее
готовых ответов.

---

## Кому это адресовано

Нужно знать C++ на уровне «умею шаблоны, умные указатели и RAII». Знание Vulkan или Metal **не
требуется** — оба разбираются с нуля. Потребуется базовая линейная алгебра для главы про 3D.

Что вы получите к концу: работающий рендерер, который на Windows и macOS даёт побайтово
одинаковую картинку из одного и того же кода приложения, и — что важнее — понимание, откуда
берётся каждое архитектурное решение.

---

## Дорожная карта

Порядок не случаен: каждый следующий блок опирается на предыдущий, и почти каждый решает
проблему, которая **возникает** в предыдущем. Это осознанная драматургия — сначала натыкаемся,
потом исправляем.

```
Часть I   Фундамент                     ← окно, устройство, свопчейн, синхронизация
   │                                       результат: чёрное окно, которое не падает
   ▼
Часть II  Первый кадр                   ← шейдеры, пайплайн, проход, буферы
   │                                       результат: сетка на экране
   ▼
Часть III Абстракция                    ← интерфейсы, второй бэкенд, ImGui
   │                                       результат: то же самое на двух API
   ▼
Часть IV  Память                        ← staging, VRAM, бюджет, суб-аллокатор
   │                                       результат: геометрия в видеопамяти, контроль расхода
   ▼
Часть V   Текстуры                      ← загрузка, мипы, сэмплеры, 3D/куб/массивы, сжатие
   │                                       результат: настоящие текстуры вместо процедурных
   ▼
Часть VI  Проходы и состояния           ← MRT, оффскрин, смешивание, глубина, MSAA
   │                                       результат: многопроходная схема со сглаживанием
   ▼
Часть VII Производительность            ← push-константы, кэш привязок, indirect, readback
   │                                       результат: тысячи объектов без просадки
   ▼
Часть VIII Ловушки и что дальше         ← системные различия, отладка, честный список дыр
```

## Принципы, которых курс придерживается

**Сначала проблема, потом решение.** Ни одна абстракция не вводится «на будущее». Сначала
пишется код, который упирается в ограничение, и только потом появляется механизм, который его
снимает. Так видно, за что именно платим сложностью.

**Проверяемость важнее красоты.** Каждая глава заканчивается способом убедиться, что работает
именно то, что задумано — не «выглядит правильно», а измеримое доказательство. Слои валидации
включены с первого выпуска.

**Ошибки не вырезаны.** В тексте остались реальные промахи разработки: перевёрнутая картинка
из-за разных систем координат, гонка при частичном обновлении буфера, невалидный тестовый
стенд, который выглядел как поломка библиотеки. Каждая — отдельный поучительный сюжет.

**Никаких «магических» строк.** Если в коде появляется константа или флаг, он объясняется.
Скопированный без понимания шаблон — главная причина, по которой люди бросают Vulkan.

## Как устроена каждая глава

```
Цель                    что будет уметь код к концу
Теория                  как это работает на железе и почему API так выглядит
Реализация              пошагово, с полным кодом
Подводные камни         что сломается и как это выглядит
Проверка                как убедиться, что работает
Итог и что дальше       связка со следующей главой
```

## Исходный код

Структура проекта, к которой мы придём:

```
render_pipeline/     абстрактные интерфейсы — единственное, что видит приложение
render_vulkan/       бэкенд Vulkan
render_metal/        бэкенд Metal
shaders/glsl/        шейдеры для Vulkan
shaders/metal/       шейдеры для Metal
FastRenderer.cpp     цикл кадра — один на обе платформы
main.cpp             точка входа
```

Ключевое свойство итоговой архитектуры: **весь выбор бэкенда живёт в одном файле**
(`render_pipeline/RenderHelper.cpp`). В цикле кадра нет ни одной директивы условной компиляции.
